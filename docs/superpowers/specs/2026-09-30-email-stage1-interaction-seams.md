# Stage 1 interaction seams

The Email module owns mailbox semantics, provider locators, Reply-To/Reply all rules, MIME construction and provider effects. The generic host owns current human identity, account-target consent, draft/file custody, exact confirmation and durable Run authorization. A Worker proposal, guessed file ID, synchronized email header or provider URL does not become trusted authority.

## Current outgoing proposal boundary

`examples/apps/email/outgoing-snapshot.mjs` implements and tests the Email side of an immutable plain-text outgoing snapshot. Its caller supplies only account ID, draft ID and expected revision. Injected trusted host ports must resolve the current draft and verified sender, seal exact bytes, verify current custody/authority and reserve the operation. There is no default permissive port. The module supplies no host persistence, signing keys, upload endpoint or authorization.

The snapshot binds organization/owner/installation/account/authority epoch, verified From, deduplicated To/Cc/Bcc, subject, draft revision, reply parent and References, body/file byte counts and digests, MIME bytes/digest and transport kind. Files must be finalized, unexpired and belong to that draft or its authorized reply parent in the same account. Received Bcc is never copied into Reply all; Reply-To wins and own aliases are excluded. Bytes and metadata are copied before asynchronous verification to prevent substitution.

Gmail/Graph raw MIME retains Bcc for submission; SMTP omits the header and uses a separately bound envelope containing all recipients. A replay returns identity metadata without transport bytes, and an unknown reservation cannot resend. Snapshot reservation governs immutable confirmation; the provider operation journal separately governs the transport attempt. They must be separate state machines, with the same operation/snapshot identity, rather than two competing reservations in one ledger.

The existing host human-action path still provides current-authority capture, exact bounded scalar input, a sealed confirmation ticket and durable idempotency. It preserves one-click human Send without a separate approval queue. Large rich inputs must use a reviewed generic reference contract and custody endpoint before the Email snapshot proposal can be integrated; serializing unchecked mail/files into a scalar is not an acceptable shortcut.

## File media and custody

Incoming attachment custody already encrypts bytes, binds the exact owner/resource/checkpoint/parent body, verifies sizes/content fingerprints and rechecks current owner, parent generation and consent after I/O. PDF support is an additive reviewed media declaration. It is download-only with attachment disposition and nosniff; bounded signature/trailer classification is not sanitization or malware certification. Existing retained consent must not automatically acquire a newly declared media type.

The workspace upload endpoint has message/task or unlinked uploader ownership, but no App draft/target finalization contract. Do not attach private outgoing Email drafts to shared workspace messages merely to reuse that endpoint. A generic private App file stage, current-target checks, finalized byte identity and retention/cleanup are still required for outgoing files. Safe reader rendering and remote-content controls remain separate from binary download classification.

## Metadata expansion

Logical provider metadata uses a separate `mail_index` descriptor and experimental indexed candidate. The current closed Kit/host contract permits one Experience per package, so main `1.5.7` keeps its legacy Inbox/private-state/action path and the same App identity at `1.5.7-indexed.1` is an explicitly reviewed read-only alternative. No legacy grant changes implicitly. The indexed bundle uses v2 with no private-state property; v3 requires nonempty private state in the existing host normalizer. Metadata records contain stable account/logical/conversation identity, bounded headers/flags/folder membership and explicit lazy body/file state. Provider locators stay in the private service index. A metadata row cannot route a legacy IMAP action by guessing its locator. Merge into the main journey only after reviewed lazy reader/compose/file seams can replace the legacy path coherently.

Provider services receive current purpose-scoped Runtime sessions and exact trusted account-to-binding mappings. They cannot substitute an owner bearer, administer the workspace or infer authority from a mailbox address. Email-owned OAuth/provider verification and encrypted POSIX custody now implement the isolated module ports, with tested one-use browser state, verified subject/scopes, durable setup generations and refresh crash fencing. The current host lacks the owner/target/account authority projection and authenticated connection/callback integration needed to invoke them. Deployment OAuth registration and normal owner connection/reconnection UI remain gates; see the owner connection decision and `examples/apps/email/providers/oauth-custody.md`.

## Integration exit

### Saved draft revision at human confirmation

The next bounded host step binds the existing scalar human ticket to an optional exact private-state draft reference and content digest. The host rederives the reviewed declaration, takes the existing owner/state advisory lock before phased authorization locks, resolves encrypted custody and checks CAS at both preparation and confirmation. Shared action/draft fields must agree. The established Run store persists immutable action input and the existing draft-derived idempotency key governs duplicate confirmation and lost-response lookup.

This is preferred to adding a second snapshot/operation table for the current scalar composer: a new table would duplicate existing encrypted tickets, immutable Run input and submission lookup without solving outgoing file or nested content contracts. This bounded scalar draft reference is implemented and passes actual HTTP stale revision, draft mutation after preparation, wrong target/owner/key, input mismatch, deletion and repeated-confirmation checks, plus legacy direct request compatibility. Preparation and confirmation retain the existing conservative private-access clock across SQL sample dispatch/response and final authority I/O; two actual-service skew/delay regressions failed before repair and pass afterward. The actual composer supplies its confirmed saved revision. No schema migration is needed. Full Email MIME/file snapshots still require their separately reviewed generic reference contract; no unchecked JSON scalar is introduced here.

Close X03 only after the actual host UI resolves sender, recipients, content and finalized files to the exact snapshot captured at confirmation and dispatch, with substitution/revocation/replay tests through that host endpoint. Close X06 only after two controlled Deft-connected accounts exercise full conversation, Reply all, PDF, reload recovery, sender choice, one Send and controlled-recipient/Sent verification, independent revoke and accepted-response-loss reconciliation. Mock provider tests and the current rendered fixture harness cannot satisfy those exits.
