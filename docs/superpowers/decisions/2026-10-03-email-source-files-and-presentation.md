# Source-backed incoming files and hosted message presentation

Root architecture approval: incoming file inspection and hosted message formatting derive only from the current separately reviewed original `message/rfc822` source read. No mailbox scope, manifest disclosure, attachment-sync retention, Worker document ceiling or SDK operation changes.

The former `openResource` viewer required a retained projection, so fresh provider Inbox references could not inspect attachments. Reusing the EML download alone would force users to extract files manually. Storing provider attachments as new projections would add retention and migration requirements. The selected path adds a private adapter `readSourceFiles` seam and hosted `list_files`, `read_file`, `read_presentation`, `read_image` operations mapping to the existing `read_source` purpose.

Each read resolves the exact current owner/session/account resource and current deployment adapter. The source remains provider bytes, not display reconstruction. Opaque file/image selectors hash the complete source digest plus authoritative part/image position; selectors are not capabilities. A byte read re-fetches the current source and recomputes the selector, denying changed source. Fresh authority and exact source-record identity are rechecked after every provider/parse/proxy boundary. No provider locator, token, remote URL or bytes enter the Worker. Wrong account, withdrawn grant, expired reference, source change and abort withhold output and wipe captured buffers.

Limits: original source at most the reviewed ceiling, never more than8MiB;256 multipart delimiters;64 multipart/embedded-message headers;32 decoded files with aggregate decoded bytes at most the source ceiling;8192 HTML nodes/depth64; hosted HTML and plain fallback each256KiB UTF-8. Parsing does not decompress archive contents. Over-limit inspection fails honestly. Source HTML truncation is explicit; original EML download preserves complete bytes. Hosted output stays in a selected-message ephemeral surface. Every image byte request still re-reads the source; this implementation does not introduce an adapter MIME cache.

Preview: strict UTF-8 text/plain, text/csv and JSON; structurally checked PDF; signature/dimension checked PNG/JPEG/GIF/WebP; at most2MiB per preview/image,4096 edge and4million pixels. Other MIME types, HTML/SVG, spoofed types, unknown dimensions or larger files remain download-only. Files download as octet-stream with safe bounded filenames and nosniff. PDF uses an already-fetched application/pdf Blob and a real user-click separate browser tab, noopener/noreferrer, never a sandboxed blank iframe or an after-await popup. Source/account expiry and unmount revoke URLs.

CID nominations derive from exact parsed source HTML and unique safe image parts. Remote nominations derive from the same source, are never client URLs, and require an explicit per-message action. The separate proxy rejects non-HTTPS, credentials, nonpublic DNS answers and redirects, pins TLS requests to checked public addresses, uses no caller/provider headers and performs fresh authority checks before outbound I/O and after responses. The host loads at most two images concurrently and retains at most8MiB encoded image bytes for a message. All image URLs are revoked on source removal, suspension or expiry. Ordinary view rerenders reattach the same ephemeral hosted surface without aborting its source read or reloading successful images.

Current document failure can fall back through the explicitly reviewed source lane, returning only bounded plain text and the already-reviewed document metadata to the Worker. Account identity/verified own aliases come from current encrypted custody; message headers remain untrusted email headers, independently validated. Reply admission still independently resolves the provider parent/thread. Full hosted Print uses authoritative parsed source headers and only already loaded CID bytes. Expired hosted print does not fall back to a stale leaf.

Acceptance: public service reproduction before/after; actual native factory retained and transient source fixtures; source-digest substitution/wrong-account/revocation/abort/limits/malicious MIME tests; actual hosted React PDF/PNG/text/unsupported/empty/unavailable fixture; image controller rerender/truncation/aggregate budget cleanup tests. Final live PDF page/download hash, exact selected-message rendering and deployment remain root-owned gates. No provider writes or deployment were performed by this lane.

Host source policy lookup uses the existing read-only `/access/review` preparation, normalized and matched to the active exposure review digest, artifact and bundled resource membership. The short-lived current Worker cache retains only the digest/snapshot, never the review token; replacement/account/session/grant change invalidates the lifetime. Expired snapshots deny the current operation and are discarded so a later explicit operation can read a fresh snapshot. This adds one initial review round trip before a source operation; no access acceptance/acquisition or expanded permission is performed. The content service independently enforces fresh authority for each byte read.


### Current technical lease for hosted source policy

The running Worker can renew its authenticated technical lease without replacing its React bootstrap exposure snapshot. Hosted source policy must use the renewed lease expiry, while requiring the same exposure ID, epoch and review digest as that bootstrap snapshot. The current normalized review still must match the artifact and exact bundled resource, remain unexpired, and admit read_one/source. The content route continues fresh authority checks on every read. No captured expiry is edited and no permission is extended locally.

The focused regression reproduced the initial expired-snapshot denial (3 passed, 1 failed), then passed all four checks using an actual createExperienceLease renewal. Rotated exposure ID/epoch/digest, expired renewed authority and retired lifetime continue to deny. This decision was approved by the root architecture review before implementation; final live source rendering remains pending.
