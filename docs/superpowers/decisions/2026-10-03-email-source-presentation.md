# Source-backed message presentation

The ordinary reader must display newsletters, receipts, tables and embedded images without passive tracking or an App-controlled fetch capability. The original-message permission already bounds message/rfc822 at 8 MiB. The App document leaf remains 16 KiB. Increasing that leaf and the Worker wire budget would unnecessarily expose larger private documents to the App.

The trusted host instead requests a selected record's presentation through the current original-source authority. It retains the existing small body while that request is pending. The host presentation has an explicit 256 KiB ceiling and truncation notice. The backend parses the exact source to nominate CID or remote image references; each reference is bound to that source and current record. The App receives neither attachment bytes nor provider image locators. The host sanitizer only recognises backend-rewritten image markers in the matching manifest.

Presentation stays in the host DOM rather than introducing another email iframe. A small allowlist admits bounded local colours, typography, spacing, legacy table alignment/size attributes and table borders. Stylesheets, global selectors, fixed positioning, generated content, CSS variables, URL-bearing values and author classes are excluded. Parsing starts in an inert template. Active HTML, SVG, forms, event handlers, image sources and navigation credentials are removed. Tables may scroll inside the document; the document itself must fit the mobile pane.

CID images use the same governed incoming-file byte lane. External images remain blocked until the user explicitly loads them for this message. The proxy only receives a URL resolved from the exact authoritative nomination, never a client URL. It accepts HTTPS on port 443 without credentials, checks every resolved address against public-address rules, pins HTTPS to a vetted address and revalidates every redirect. It forwards no provider or caller credentials, cookies or referrer. A mandatory fresh authority callback runs before DNS, before every outbound request and after every response. Cancellation, denial or expiry discards the result.

Raster image responses are limited to 2 MiB, 4096 pixels per edge and four million pixels per frame. PNG/APNG and WebP animation are excluded; GIF has a maximum of 32 frames and sixteen million aggregate frame pixels. JPEG, non-animated PNG/WebP and bounded GIF are supported; SVG is excluded. The host owns object URLs and revokes them when the selected message or authority changes. Concurrency must be bounded; in-flight source reuse cannot cross owner, account, record, source or session boundaries.

Print uses an optional generic document `print_control_id` linked to one button in the same current view. Missing, duplicate, non-printable or stale references fail closed. This lets an App place Print in its normal action menu without teaching the host any Email identity. The native handler prints the exact safe document, not an App-supplied action payload. Printing acquires no images: only already loaded CID object URLs enter its sandboxed print document, with literal title/header metadata and a restrictive CSP.

Evidence consists of focused presentation, proxy, bridge and renderer regressions; actual desktop/mobile newsletter and hostile HTML fixtures; governed incoming-source/CID contract checks; and the selected-message integrated host flow. Synthetic proxy fixtures do not establish live provider delivery or unrestricted HTML compatibility. Body/source/image ceilings and blocked CSS remain product limits.
